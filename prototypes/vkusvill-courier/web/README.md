# Экран курьера — рабочая версия

Концепт мотивационного слоя для курьеров. **Не официальный продукт ВкусВилл**,
имена и цифры вымышлены.

В отличие от статических прототипов рядом (`../app.html`, `../index.html`),
здесь ничего не нарисовано: всё на экране считает движок правил из журнала
событий.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 83 теста: движок + хранилище
npm run bundle   # собрать всё в один ../app-engine.html
```

## Как устроено

```
события смены  →  движок правил  →  снимок состояния  →  экраны
(журнал)          (rules.ts)        (Snapshot)           (screens.ts)
```

```
src/
  engine/
    types.ts        типы событий, правил и результата
    rules.ts        ПРАВИЛА — данные, ни одного if; с историей изменений
    engine.ts       evaluate(events, rules, ctx) → Snapshot, чистая функция
    summary.ts      неделя словами — абзац из того же снимка
    days.ts         порядок дней недели: соседние ли дни
    text.ts         склонения и форматы
    engine.test.ts  64 теста
  state/
    scenarios.ts    три недели курьера — журналами событий, а не состояниями
    appeals.ts      что можно оспорить, причины, заявки
    store.ts        хранилище, localStorage, подписки (store.test.ts — 19 тестов)
  ui/
    screens.ts      шесть экранов, читают Snapshot
    components.ts   карточки, кольцо, полосы, шторки
    simulator.ts    панель «подать событие»
    app.ts          оболочка, навигация, свайп, установка на экран «Домой»
```

### Движок — чистая функция

`evaluate(events, rules, ctx)` не хранит состояние и ничего не мутирует.
Состояние курьера каждый раз пересчитывается из полного журнала. Отсюда три
следствия, ради которых так и сделано:

1. **Правила можно менять задним числом** и сразу видеть, что получилось бы.
2. **Спор «почему у меня такой балл» разрешается предъявлением журнала** —
   на вкладке «Лента» видно каждое событие и его вклад.
3. **Всё тестируется без браузера.**

### Правила — данные, с историей

`rules.ts` — таблица «событие → последствие». В боевой системе этот файл лежал
бы в конфиге и правился без релиза в сторах: иначе каждая правка механики стоит
две недели раскатки, а править придётся постоянно.

Чтобы поменять цену смены с 12 баллов на 15, достаточно одной строки:

```ts
{ on: 'shift_closed', match: { clean: true }, add: 15, bucket: 'slots', label: 'Смена без замечаний' },
```

У правил есть версия, дата и список изменений (`changes`). Курьер читает их
целиком в шторке «Правила» — таблица баллов, уровни, порог раннего доступа,
причины «не по моей вине», нагрузка и раздел «чего в правилах нет». По 289-ФЗ
платформа обязана раскрывать принципы рейтинга и объяснять изменения
алгоритма; здесь это часть правил, а не примечание к релизу.

### Чего в правилах нет намеренно

| Нет | Почему |
|---|---|
| Скорости доставки и времени в пути | Соревнование за скорость на велосипеде оплачивается травмами. Комплимента «быстро» тоже нет |
| Серий без выходных | Streak с обнулением заставляет выходить больным. Единственная «серия» в системе — дни подряд — работает наоборот: после шести приложение предлагает выходной |
| Влияния уровня на поток заказов и ставку | Тогда это не игра, а система оплаты труда — с обязанностью раскрывать алгоритм (289-ФЗ) |
| Штрафа за инцидент | Штраф за ДТП заставляет их скрывать, а нужно ровно обратное |
| Баллов за «спасибо» | Иначе их начнут выпрашивать и обменивать. Спасибо идёт в ленту и в знак — и потому ему верят |

Последнее про инцидент покрыто тестом: `инцидент не отнимает баллов`.

## Не по моей вине

Кнопка «Не по моей вине» открывает шторку со списком спорных событий недели:
жалобы, оценки 1–2, пропуски без предупреждения. У каждого — причины из
таблицы `excuses`:

- **Подтверждает система** (сборка на точке с опозданием, погода, сбой
  приложения, инцидент в этот день) — применяется сразу, без заявки.
- **Проверяет управляющий** (клиент не открыл, здоровье, другое) — заявка,
  до решения ничего не меняется. Демо-кнопка «решение управляющего»
  показывает, что происходит дальше.

Решение — это не удаление и не ручная правка цифр. Событие получает пометку
`excused` и **остаётся в журнале с причиной**: в ленте оно видно с зачёркнутой
ценой. Движок его нигде не считает — ни в балл, ни в среднюю оценку, ни в
счётчики, ни в сброс знаков — и всё пересчитывается само. «Забыли поправить
рейтинг после удовлетворённой жалобы» здесь невозможно по построению.

Это тот же ход, что Uber сделал в 2026 году с пересматриваемыми рейтингами
«при обстоятельствах вне контроля водителя», и то, чего требуют 289-ФЗ и
европейская директива о платформенной занятости: объяснение и человеческий
пересмотр.

## Неделя словами

`summary.ts` собирает абзац из снимка: смены, доставки, оценка, что не так,
что не учтено, что закрылось, до чего ближе всего, пора ли выходной. Без ИИ,
шаблоном — поэтому цифры в тексте не могут разойтись с кольцом. Если текст
когда-нибудь будет переформулировать языковая модель, на вход ей пойдёт
ровно этот абзац, а не сырые данные: она не сможет сказать ничего, чего нет
в журнале.

## Нагрузка и инцидент

Единственные правила про время работают в обратную сторону. Часы за неделю
(`shift_closed.hours`, по умолчанию 6) считаются против потолка 60. Рабочие
дни подряд считаются по календарю — «Пн, Ср, Пт» это не серия — и после
шести приложение показывает карточку «возьми выходной» с кнопкой «Освободить
завтрашний слот»: это обычное событие «слот освобождён заранее», 0 баллов,
серия на нём обрывается. В симуляторе «Закрыл смену» завершает день, так
что шестую смену подряд можно набрать в один клик.

После инцидента на «Смене» появляется порядок действий — ты в порядке,
позвони на точку, заказ повреждён — и кнопка «Я в порядке». Инцидент убран
из «Что подтянуть»: падение — не то, что подтягивают.

## Тёплые слова

Событие `kudos` — спасибо от коллеги с именем и словами. Оценка может нести
комплимент клиента (`compliment`: вежливый, аккуратно с продуктами, помог
донести, забрал тару). И то и другое — отдельные строки ленты, чипы «Тёплые
слова» на «Прогрессе» и «Команде», знак «Спасибо с точки» за десять. Баллов
не стоят.

## Лента

Отдельная вкладка. Вехи — «знак получен», «счётчик пошёл заново», «поднялся
уровень», «изменился доступ к слотам», «пора выходной» — не выписываются
руками: движок строит их, сравнивая состояние до и после каждого события.
Поэтому лента не может разойтись с экранами, это буквально одно и то же
условие.

Цена — пересчёт на каждом префиксе журнала, O(n²). При недельном журнале это
доли миллисекунды; если журнал станет длиннее месяца, понадобится
инкрементальный проход.

Повторы сворачиваются: тридцать две подряд «Оценка 5» — одна строка с `× 32`
и суммой. Точка на вкладке показывает, сколько записей добавилось с прошлого
открытия; она гаснет, когда ленту открыли.

Блок «Скоро» — три ближайших недостигнутых порога, чтобы человек знал, ради
чего следующая смена.

## Симулятор

Панель справа от телефона (снизу на мобильном) подаёт события в журнал.
Нажмите «Провёл новичка» — балл вырастет на 10, место в лиге поднимется.
Нажмите «Пропустил слот» трижды — на экране «Слоты» появится предупреждение
о приостановке раннего доступа, с причинами и порогом. Нажмите «Закрыл
смену» в ровной неделе — шестой день подряд, и появится карточка про выходной.

## Установка на телефон

Страница объявляет манифест (собирается на лету — у одного файла нет соседей,
а `start_url` должен быть абсолютным), цвет темы и иконку для iOS. В Chrome
на Android появляется кнопка «Установить», на iPhone — «Поделиться → На экран
„Домой“». Сервис-воркера и офлайн-кэша нет намеренно: пока прототип меняется
каждую неделю, закэшированная старая версия вредит больше, чем помогает.

## Доступность

Цели нажатия не меньше 34 px (вкладки — 44), фокус уходит в шторку при
открытии и возвращается на кнопку при закрытии, Escape закрывает, у кнопок с
иконками есть подписи, контраст текстовых пар ≥ 4,5:1 в обеих темах,
анимации выключаются при `prefers-reduced-motion`.

## Что здесь ещё не настоящее

- **Сервера нет.** Состояние живёт в `localStorage` этого браузера.
  Лига и командный челлендж считают своего курьера по-настоящему, а соседей
  берут из конфига — чтобы они стали живыми, нужен бэкенд.
- **Персональных данных нет** и в таком виде не появится. Как только появятся
  геолокация и поведенческий профиль, включается 152-ФЗ со всеми требованиями
  к хранению.
- **Причины «подтверждает система» подтверждаются мгновенно.** В бою они
  сверялись бы с данными точки, метеосводкой и журналом сбоев.
- **Решения по заявкам принимает демо-кнопка.** В бою их принимал бы
  управляющий точкой в своём интерфейсе — его здесь нет.
